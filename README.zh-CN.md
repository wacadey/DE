# 数据生成（DATA GENERATION）

- 数据从哪里产生？
  - 目标
    - 生成虚拟数据（假设路径为客户端 → 服务 → 生成的数据），直接写入数据湖 S3
      - 数据应包含正常和异常数据，并设置合理比例
    - 为此先在本地使用 Python 实现，再部署到 AWS ECS + Fargate
  - 确定领域 → 获取真实数据样本和缺陷率 → 构建项目
  - 形式
    - [v] 直接生成最终形态的虚拟数据并写入
      - 编写 Python 代码（使用 Faker 包）
    - 构造真实请求 → 经过服务 → 获得结果 → 写入
      - 最终项目形态
  - 方式
    - [v] ECS Fargate + k6 等，用于模拟客户端请求
      - 构建小型项目
    - AWS Distributed Load Testing，用于产生大规模流量

- 领域
  - 应用程序（Web、App）
  - IoT 传感器
  - 游戏服务器
  - 金融系统
  - 数据库
  - ……

# 数据摄取（DATA INGESTION：如何取得已产生的数据？）

- 按采集方式划分的管道类型（首次产生 → 存储）

```
                         数据摄取

                   数据源（原始数据）
              需设定每秒/每分钟的数据产生量
                           │
        ┌──────────────────┼───────────────────┬────────────┐
        │                  │                   │            │
        ▼                  ▼                   ▼            ▼
 [V] 日志/事件摄取    [V] 流式摄取           CDC 摄取     [V] 批量摄取
        │                  │                   │            │
        ▼                  ▼                   ▼            ▼
 CloudWatch Logs     Kafka/MSK/Kinesis    DMS/Debezium  CSV/API/数据库导出
 Firehose                                             （Airflow/MWAA）
        │                  │                   │            │
        └──────────────────┼───────────────────┴────────────┘
                           ▼
                    S3（数据湖）青铜层
                       保存原始数据
```

- 日志/事件摄取管道
  - 采集并保存日志和事件
  - 目标不是实时分析，而是安全积累数据；使用时间可能是当天、一周或一个月后，并不强调即时性

```
┌─────────────────────────────────────────────────────┐
│              01. 日志/事件摄取管道                  │
└─────────────────────────────────────────────────────┘

                   日志生成器
                       │
                       ▼
                CloudWatch Logs
                       │
                       ▼
             Amazon Data `Firehose`
          按时间或容量聚合后传输，因此会产生延迟
                       │
                       ▼
                   S3 青铜层
                   保存原始数据
```

- 批处理摄取管道
  - 按固定周期处理已积累的数据 → Airflow
  - Airflow/MWAA 与 Step Functions + Lambda：后者为无服务器方案，成本较低
  - 调度示例：每天一次、每天 12 点等

```
┌─────────────────────────────────────────────────────┐
│                 02. 批处理数据管道                  │
└─────────────────────────────────────────────────────┘

                   日志生成器
                       │
                   `Airflow`
             编写调度和 DAG，进行数据预处理
                       │
                       ▼
                   S3 青铜层
                       │
                       ▼
                   `Airflow`
             编写调度和 DAG，进行数据预处理
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
       Pandas（小）  Polars（中）  Spark（大）  ← 按数据规模选择
       10³ GB 以内     数十 GB      数百 GB/数 TB
          │            │            │
          └────────────┼────────────┘
                       ▼
                   S3 白银层
                       │
                       ▼
                   S3 黄金层
                       │
                       ▼
                Athena / Redshift
```

- 实时流处理管道
  - 数据进入的同时立即处理
  - 适用于工厂设备/生产异常检测、金融异常交易检测、游戏、实时订单量等
  - Kafka/MSK、Kinesis（ELK、EFK、OpenSearch 可供参考）负责传输
  - Flink 实时加工和预处理实时数据

```
┌─────────────────────────────────────────────────────┐

                       ▼
                Spark Streaming
                       或
                   [V] Flink

                  窗口/聚合

          ┌────────────┼─────────────┐
          ▼            ▼             ▼
```

# 数据存储（DATA STORAGE）

- 将采集的数据存到哪里？
  - 必须保存原始数据，不能丢失
  - 若采集过程中因故障等发生遗漏，则执行回填（重新采集并补齐遗漏部分）
- 保存期限
  - 仅保存固定期限（通常为 7 天，可调整）：Kafka、Kinesis
  - 永久保存：数据湖 → S3（对象存储，以桶为单位管理并支持搜索）
- 数据存储格式的演进
  - CSV → JSON → Parquet（面向分析的列式格式）

```
    数据摄取
        │
        ▼
    S3 青铜层
───────────────
  原始 JSON  => *.json, *.json.gz
  原始 CSV   => *.csv
  原始事件
  原始日志
  CDC 数据
----------------- => *.parquet
```

- 文件格式及用途

| 分类 | 代表性扩展名 | 主要用途 |
| --- | --- | --- |
| **结构化数据** | `.csv`, `.tsv`, `.xlsx` | 销售额、客户、订单等表格数据 |
| **半结构化数据** | `.json`, `.jsonl`, `.xml`, `.yaml` | API 响应、事件、日志 |
| **分析用列式格式** | `.parquet`, `.orc` | Athena、Spark、Glue 分析 |
| **大数据格式** | `.avro` | Kafka、Spark、数据管道 |
| **日志文件** | `.log`, `.txt`, `.json`, `.json.gz` | Web/API/应用程序日志 |
| **压缩文件** | `.gz`, `.zip`, `.tar.gz`, `.bz2` | 减少存储空间和传输量 |
| **图像** | `.jpg`, `.png`, `.webp`, `.gif`, `.svg` | 商品图片、机器学习数据 |
| **视频** | `.mp4`, `.mov`, `.avi`, `.mkv` | 监控录像、内容、机器学习数据 |
| **音频** | `.mp3`, `.wav`, `.flac` | 语音数据、AI 训练 |
| **文档** | `.pdf`, `.docx`, `.pptx`, `.hwp` | 文档归档 |
| **数据库备份** | `.sql`, `.dump`, `.bak` | 数据库备份 |
| **ML/AI 模型** | `.pkl`, `.joblib`, `.pt`, `.pth`, `.onnx` | 模型制品 |
| **Web 文件** | `.html`, `.css`, `.js` | 静态网站 |
| **二进制文件** | `.bin`, `.dat` 等 | 其他应用程序数据 |

- 按奖牌架构组织存储，并应用分区

# 数据处理（DATA PROCESSING）

- 如何处理已积累的数据？
- 分为批处理和流处理

```
                         数据处理

                        S3 青铜层
                            │
              ┌─────────────┴───────────────┐
              │                             │
              ▼                             ▼
            批处理                         流处理
              │                             │
              ▼                             ▼
[V] Airflow/MWAA                    Spark Streaming
/[V] Step Functions + Lambda         / [V] Flink（数据处理）
              │
              ▼
     Pandas / Polars / Spark（数据处理）

- 在 Airflow 内部构建 DAG，并在其中使用 Pandas、Polars、PySpark 等编写任务
  - 在 EC2 等服务器上部署会产生持续费用；放在基础设施外部（如本地）则可能引发安全问题
  - 也可使用 MWAA
- 在 Step Functions 中编排 Lambda，并在 Lambda 内使用 Pandas、Polars、PySpark 等编写任务
  - 无服务器，仅在使用时产生费用
```

- 处理策略：ETL、ELT
  - 可在数据管道中按需组合使用
  - ETL 是传统方式
  - ELT 是后来出现并正在普及的方式

```
                      处理策略

               ┌─────────┴─────────┐
               │                   │
               ▼                   ▼
              ETL                 ELT

             提取                 提取
               ↓                   ↓
             转换                 加载
               ↓                   ↓
             加载                 转换
```

- ETL 管道
  - Extract、Transform、Load，是数据工程中的传统模式
  - 可用于奖牌架构，并描述各层的数据形态

```
┌─────────────────────────────────────────────────────┐
│                    04. ETL 管道                     │
└─────────────────────────────────────────────────────┘

          数据源 / S3 青铜层
                  │
                提取  ← Pandas / Polars / Spark / Glue
                  │      （ETL、数据库、表、爬虫等）
                  ▼
                转换  ← Pandas / Polars / Spark / Glue
                  │
                  ▼
                加载  ← Pandas / Polars / Spark / Glue
                  │
                  ▼
              S3 白银层
                  │
                  ▼
              S3 黄金层
```

- ELT 管道
  - 可用于金融项目；数据先存储，再用 SQL 转换，也可应用于制造业

```
┌─────────────────────────────────────────────────────┐
│                    05. ELT 管道                     │
└─────────────────────────────────────────────────────┘

                  数据源
                    │
                   提取
                    │
                    ▼
                   加载
                    │
                    ▼
              S3 / Redshift
                    │
                    ▼
                 SQL 转换
                    │
                    ▼
               白银层/黄金层
                    │
                    ▼
                  分析集市
```

# 数据建模 / 架构（DATA MODELING）

- 如何分层管理数据
- 奖牌架构是一种可选方案，并非必须采用
- 该架构用于管理数据处理的结果

```
                       奖牌架构

  ┌───────────────┐
  │    青铜层     │
  │    原始数据   │
  └───────┬───────┘
          │
        数据处理 → 数据清洗、预处理、衍生变量等
          │
          ▼
  ┌───────────────┐
  │    白银层     │
  │  清洁/有效数据│
  └───────┬───────┘
          │
        业务逻辑 → 按数据的最终目标加工
          │
          ▼
  ┌───────────────┐
  │    黄金层     │
  │    分析数据   │ → 最终数据形态
  └───────────────┘
```
